# 自动灭世光耀广场资源门槛修复设计

## 目标

自动灭世路线已完成 `light_square` 研究且持有至少 1 点“光”时，智能建造应将光耀广场加入建造队列，并持续建造至路线要求或游戏建筑上限；不得因“光”没有普通资源产量或容量而错误停住全部流程。

## 根因

- 光耀广场需要特殊资源 `light`，但智能建造的资源快照只包含普通生产资源。
- 路径规划器遇到快照中缺失的资源时会标记 `resource-cap` 阻塞，并把对应建筑目标输出为 0。
- “光”属于持有型特殊资源，不适用普通资源的容量与每秒产量判断。

## 设计

- 将 `light` 纳入智能建造资源快照。
- 增加静态特殊资源分类；对 `light` 只比较当前持有量与本次需求，不检查 `max` 或 `speed`。
- 当前“光”不足时保留明确的资源阻塞状态；达到需求时允许光耀广场进入正常建造队列。
- 不绕过光耀广场的研究条件及其他石材、建筑材料、晶体、光明石等普通资源条件。
- 光耀广场目标显式限制为其游戏建筑上限 5；即使路线或后续配置给出更高数量，也不得输出超过 5 的建造目标。

## 影响范围

- 仅调整智能建造路径规划中的特殊资源门槛与建筑目标上限处理。
- 不修改手动建造配置、军队、攻击、探索或祈祷逻辑。
- 当前自动灭世路线仍以 5 座光耀广场作为完成目标。

## 验证

- `light > 1`、`light_square` 已完成且光耀广场未满 5 座时，规划节点状态为可排队，输出目标不超过 5。
- `light < 1` 时，节点保持资源不足状态，不错误尝试建造。
- 普通资源不足或研究未完成时，原有门槛继续生效。
- 基础模板中的 `@version` 与 `taVersion` 同步升级到 `1.0.0.17`。
- 重新构建生成脚本，通过 `node --check` 和差异格式检查。
