# MobX 运行态集合兼容修复设计

## 目标

智能规划器应正确读取游戏运行态中的资源、研究、人口和敌人集合，无论这些集合是原生数组、MobX 类数组还是普通对象。自动灭世流程必须根据真实状态识别“光”、已完成研究及已击败敌人，避免错误阻塞光耀广场及后续路线。

## 真实存档证据

- 存档中 `light` 为 1572。
- 存档中 `light_square` 与 `dark_land` 的值均为 1。
- 同时导出的目标路径却将“光”标记为缺失，并将全部研究的当前值显示为 0。
- 使用解压后的普通数组离线运行同一规划器时，光耀广场状态为 `queued`、目标为 5，证明路线和资源数量本身正确。

## 设计

- 在游戏状态适配器中增加统一集合读取函数。
- 支持原生数组、带数字索引和 `length` 的 MobX 类数组、可迭代集合及普通对象。
- 读取单项时优先使用 `gameData.idxs[group][id]` 对应的数字索引；索引不可用时再按条目的 `id`、`key` 或同类标识查找。
- 特殊资源快照、研究完成判定和人口数量读取统一使用该适配器。
- 自动灭世敌人状态也使用统一集合读取，仍然仅以 `owned === 1` 判定击败。
- 不修改存档，不从页面 DOM 推断真实游戏状态。

## 安全边界

- 保留原生数组及普通对象的现有兼容路径。
- 找不到集合或条目时返回空集合或未完成状态，不抛出异常。
- 不改变建筑目标、研究路线、资源门槛、攻击胜率及持续消耗规则。

## 验证

- 使用用户提供的真实存档验证 `light=1572`、`light_square=1`、`dark_land=1`，光耀广场节点进入队列且目标为 5。
- 使用 `Array.isArray(...) === false` 的模拟 MobX 类数组重复验证资源和研究读取。
- 验证敌人 `owned=0` 为未击败、`owned=1` 为已击败。
- 验证集合缺失时安全返回，不出现未捕获异常。
- 基础模板与生成脚本版本同步升级到 `1.0.0.19`。
- 重新构建生成脚本，通过 `node --check`、行为模拟和差异格式检查。
