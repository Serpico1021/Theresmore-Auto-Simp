# 人口敏感建筑批量建造设计

## 目标

降低转生前期“建造一个建筑→切换人口页→调整人口”的频率，同时保留资源安全锁，避免供应商、工匠、教授等岗位建筑连续建造导致食物或其他资源进入负增长并卡死流程。

## 行为设计

- 将新增人口、坑位和会新增工种的建筑统一视为“人口敏感建筑”。沿用现有 `popAdjustBuildingList` 作为可配置集合，覆盖房屋、农场、伐木工营地、采石场、矿井以及木匠、教授、供应商等后续建筑。
- 建造循环每次重新读取当前按钮、建筑数量和资源安全状态，因此可以跨不同建筑连续建造，不固定为单一建筑或单次点击。
- 建造人口敏感建筑后，查看规划队列中的下一个可建建筑：
  - 下一个仍是人口敏感建筑，且当前资源安全锁允许建造：继续批量建造。
  - 下一个不是人口敏感建筑、已达到上限、或安全锁不允许：停止批量建造，切换人口页并执行现有智能人口分配。
- 不使用 `maxExtra` 作为人口敏感建筑批量链的停止条件；建筑自身 goal 上限由 goal-path 过滤，批量链只在安全锁或建筑范围条件结束时交接人口调整。
- 非人口敏感建筑不触发人口调整，保持原有普通建造行为。

## 实现边界

- 复用现有 `getAllButtons`、`getButtonCount`、资源安全锁和人口执行器，不重复模拟建筑成本。
- 每次点击后等待 React 状态刷新并重新获取 DOM，避免复用失效按钮节点。
- 每次点击后必须确认目标建筑数量实际增加；通过最多 2 秒、每 100ms 一次的状态轮询等待 React/游戏状态提交。若按钮不可用，或轮询超时仍未增加（资源不足、容量不足、建筑上限等），则判定本轮建造失败并结束批量窗口。
- 若失败前本轮已经建造过人口敏感建筑，则立即进入人口调整；补足人口和资源后由下一轮继续处理未完成建筑。
- 人口调整仍通过 `executeAction$4` 完成，智能人口规划的分阶段策略不变。

## 人口安全补缺边界

安全资源只有在速度低于最低线时才算缺口；速度刚好达到最低线不再重复触发同一安全岗位。安全补缺完成后，剩余人口进入均衡阶段，按伐木工、石工、矿工、工匠轮转分配。

## 测试

- 保留现有智能人口规划和食物安全回归测试。
- 增加源码级回归断言，确认批量循环会刷新按钮、检查下一个建筑的人口敏感性和安全锁，并确认不会被 `maxExtra` 截断。
