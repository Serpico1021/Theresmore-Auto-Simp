# 自动灭世建筑预设联动设计

## 目标

选择或加载“自动灭世”目标后，脚本应自动启用建造自动化及城市、殖民地、深渊三个建造子页，并将自动灭世路线中的全部建筑数量和优先级写入配置与设置界面。用户无需导入或维护其他建筑配置。

## 配置来源

- `annihilatorRoute.buildingTargets` 是自动灭世建筑目标的唯一来源。
- 每次应用自动灭世预设时，按照路线表覆盖写入三个建造子页的建筑数量。
- 正数目标受对应建筑的游戏上限约束；光耀广场写入 5，不能超过上限 5。
- 路线值 `-1` 原样写入，继续表示建造至游戏上限。
- 每个路线建筑写入其显式优先级；未提供优先级时统一使用 6。
- 非路线建筑的数量与优先级归零，避免旧配置干扰自动目标。

## 页面联动

- 启用 Build 页面。
- 启用 City、Colony、Abyss 三个子页。
- 根据建筑数据中的 `tab` 将路线目标写入正确子页的 `options`。
- 同步页面开关、子页开关、建筑数量和优先级对应的 DOM 控件。
- 完成全部写入后，通过现有选项存储机制持久化配置。

## 运行边界

- 不改变智能规划器对研究、资源、前置建筑及持续消耗安全条件的判断。
- 不改变军队、攻击、探索和祈祷预设的现有行为。
- 只在目标为 `annihilator` 时应用该建筑预设。

## 验证

- 从 Build 及三个子页均关闭、建筑配置为空的状态加载自动灭世目标，四个开关全部开启。
- 路线中的每个建筑均映射到正确子页，数量与优先级写入配置并同步界面。
- `light_square_b` 位于 Abyss 子页，数量为 5、优先级为 6。
- 非路线建筑归零；`-1` 目标保持 `-1`。
- 自动灭世目标重新加载后结果保持一致，不依赖其他导入配置。
- 基础模板与生成脚本版本同步升级到 `1.0.0.18`。
- 重新构建生成脚本，通过 `node --check`、行为模拟和差异格式检查。
