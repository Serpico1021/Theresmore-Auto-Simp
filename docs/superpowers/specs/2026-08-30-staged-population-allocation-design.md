# 分阶段人口分配设计

## 背景

月明之夜和速刷超转生路线在首轮月明之夜可能没有工匠工会。当前人口规划器在尝试填入供应商前，先用资源安全检查拒绝会造成食物或奶牛负增长的岗位，导致路线岗位和后续人口补足全部停滞。

## 目标

让人口规划器按明确的阶段生成一次性分配计划：先建立最低生产基础，再完成路线岗位，再修复由路线岗位引入的负增长，最后均衡分配基础生产岗位。分配结果可批量提交，不要求逐人口重新点击。

## 规划顺序

1. **基础起点**：优先填入 1 个农民。
2. **路线岗位**：按“教授 → 木匠 → 供应商”顺序，忽略本阶段因新增岗位产生的负增长，分别填到路线目标数量；数量受未分配人口、岗位当前上限和岗位可用上限约束。当前路线目标保持教授 3、木匠 1、供应商 1。
3. **缺口修复**：以第 2 阶段完成后的模拟资源速度重新计算食物、奶牛及其他安全资源缺口，优先填入饲育员和农民；每种岗位的数量按模拟结果一次计算，直到缺口消除或没有可用岗位/人口。
4. **基础均衡**：在安全资源处理后，按照伐木工、石工、矿工、工匠的轮转顺序分配剩余人口。每次轮转基于模拟后的生产速度选择相对短缺岗位，避免集中分配到单一岗位。

如果第 4 阶段后仍有剩余人口，沿现有优先级选择可用且不会破坏安全资源的岗位；没有合法岗位时保留未分配人口，等待下一轮状态变化。

## 设计边界

- 第 2 阶段的负增长检查只对路线岗位关闭；其他阶段继续使用现有资源安全约束。
- “模拟”只在规划器内部复制资源速度和人口计数，不修改游戏状态；最终由现有人口提交通道一次性提交每个岗位的数量。
- 每个规划周期从当前实际人口和资源速度开始，避免跨周期重复应用上一次计划。
- 现有路线目标、资源规则、快照重算和 UI 配置保持兼容。

## 实现位置

- 主要修改 `automation-src/fragments/smart-build-population-planner.js`。
- 将现有单岗位优先选择扩展为阶段性批量计划，并保留现有 `planJobs()` 返回结构，必要时增加批量数量字段。
- 通过纯函数测试覆盖：路线岗位允许暂时负增长、四阶段顺序、批量数量上限、缺口修复和均衡分配。

## 验证标准

- 在“无工匠工会、供应商会使食物或奶牛为负”的快照中，计划仍会完成教授、木匠、供应商路线阶段。
- 路线阶段结束后的模拟状态会触发饲育员/农民补缺，而不是再次卡在供应商。
- 有足够人口时，返回的分配计划包含各岗位的具体批量数量，而不是只返回一个岗位。
- 不影响现有普通进度路线和资源安全回退行为。
- 合并构建后生成 userscript 可通过 `node --check`。
