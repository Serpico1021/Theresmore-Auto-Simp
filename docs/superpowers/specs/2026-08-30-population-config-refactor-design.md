# 人口配置模块重构设计

## 背景与目标

当前人口模块依赖手工填写每个工种的 `Max/Prio`，并且只在 `popAdjust` 或导航栏未分配人口标记满足时进入人口页。这会导致新工种坑位出现后未触发调整，也会出现已有大量未分配人口却卡在人口任务中的情况。本次重构将智能人口配置独立为规划器，由目标路线、资源速率和当前坑位共同生成分配策略；智能人口关闭时保留原有手工配置行为。

当前实际开发重点是 `fastNgPlus`：速刷月明之夜，累计 25 个继承后超转生。`titanThenFastNgPlus` 只保留切换开关和路线扩展桩，不实现普通难度泰坦、军队准备或更高继承门槛。

## 设计原则

- 智能人口规划与页面点击执行分离。
- 资源安全阈值优先于路线优先级，禁止为单项产出破坏基础资源安全。
- 新工种出现本身就是调整事件，无论是否存在未分配人口。
- 资源优先级使用可扩展数据表，首版不追求全局最优解。
- 智能模式关闭时不改写、不替代原有手工人口配置。

## 模块边界

新增 `SmartPopulationPlanner`，分为四层：

1. 状态读取：人口总量、未分配人口、可见工种、当前工种数量与可用上限、建筑数量、研究状态和资源速率。
2. 目标计算：根据当前目标生成工种最低目标、优先级和资源安全约束。
3. 触发判定：比较轻量人口快照，识别新坑位、坑位扩容、人口建筑完成、资源速率变化和未分配人口。
4. 执行适配：复用现有页面按钮、导航和负产出检查，只负责将规划结果转换为点击动作。

建筑与研究最低目标仍由智能建筑/研究规划器生成。人口规划器不直接写建筑或研究配置，只消费人口建筑完成和研究状态变化。

## 首版目标与人口策略

### 目标路线

- `moonlightNight`：为月明之夜推进服务。
- `fastNgPlus`：复用月明路线，实际目标是累计 25 个继承后超转生。
- `titanThenFastNgPlus`：仅保存开关/路线标识和扩展接口，不执行任何泰坦或军队逻辑。

### 资源安全阈值

人口规划器以预测速率评估每次分配后的结果：

- 食物、木材、石头、铜、铁、工具：尽量保持速率大于 `1`。
- 奶牛、马：保持速率大于 `0`。
- 原料（游戏 id `building_material`）、水晶、补给：作为相对更高优先级资源，出现缺口时优先补充生产工种。
- 月明目标所需的研究资源继续由目标研究规划提供，并避免人口分配将其长期抽空。

未来可在资源表中增加权重、目标速率和路线专属优先级，不改变规划器接口。

### 月明人口路线

当基础资源满足安全阈值后，按以下顺序持续填充当前已解锁且可见的工种：

`木匠 → 教授 → 供应商`

这里的“持续填充”不是每个工种固定 1 人，而是按该顺序尽量补到当前可用上限；如果继续分配会突破资源阈值，则转向下一个安全工种或等待资源恢复。其他已解锁工种继续参与资源缺口修复、食物保底和后续可扩展优先级。

## 建筑与研究最低目标

- 若工人之家研究可研究，必须纳入研究队列并点击完成。
- 工人之家建筑目标至少为 `12`。
- 市政厅建筑目标至少为 `2`。
- 纪念碑研究对所有当前可解锁/可研究的纪念碑逐项纳入研究队列。
- 这些最低目标不能因月明路线的普通建筑偏好而被压低；资源不足时沿现有前置链等待。

## 触发与执行流程

人口任务每次进入时读取当前状态并执行以下流程：

1. 读取所有已解锁、页面可见的工种及 `maxAvailable`。
2. 与上次快照比较；新工种坑位、坑位扩容、人口建筑完成、资源速率变化或未分配人口都会触发调整。
3. 生成工种目标和排序；新工种出现时即使没有未分配人口也记录为待满足高优先级目标。
4. 按规划结果撤销不符合当前目标的分配，再逐个点击安全的新增分配。
5. 直到没有未分配人口、目标已满足或继续分配会突破阈值。
6. 保存轻量快照；相同状态不重复全量重排，但人口出现或资源状态变化时立即重试。

人口页的进入条件不再只依赖 `popAdjust` 或导航栏标记；这些旧信号可以继续作为兼容信号，但必须补充状态驱动判定，解决 21 个未分配人口仍卡住的问题。

## 普通房屋问题

移除“是否看见农场按钮”参与普通房屋决策的隐式门槛。农民数量与食物安全只用于资源预测和分配安全检查；已有 1 个农民不能阻止普通房屋达到智能目标。普通房屋仍受资源、前置研究和其他通用建筑条件约束。

## 错误处理与兼容性

- 缺少游戏状态、资源或工种数据时，规划器返回空计划，交回原有配置执行，不抛出阻断主循环的异常。
- 页面切换或按钮失效时立即停止本轮，等待下一轮状态重新读取。
- 不存在的工种、建筑或研究 id 被忽略并记录调试日志。
- 智能人口关闭、智能建筑关闭或手动覆盖模式开启时，继续使用现有手工人口配置。

## 验收与测试

至少验证以下场景：

1. 新增木匠、教授或供应商坑位时，无未分配人口也会进入调整流程并记录待满足目标。
2. 存在 21 个未分配人口时，人口页能持续分配，直到达到目标或资源安全阈值。
3. 农民已有 1 个时，普通房屋仍能按目标建造。
4. 基础资源阈值被突破风险出现时，路线工种会让位给资源保底工种。
5. 原料、水晶、补给缺口时，相关生产工种优先于普通低优先级工种。
6. 工人之家达到 12、市政厅达到 2，工人之家研究和可用纪念碑研究会被执行。
7. `fastNgPlus` 仍沿月明路线运行；`titanThenFastNgPlus` 只保存切换状态，不触发泰坦或军队行为。
8. 智能人口关闭后，现有手工 Max/Prio 配置行为不变。

实现智能人口相关 fragment 后，必须执行 `automation-src/build.ps1` 重新生成 userscript，并运行 `node --check` 验证生成文件语法。
